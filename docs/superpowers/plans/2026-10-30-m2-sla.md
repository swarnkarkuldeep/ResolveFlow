# M2 SLA Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (chosen by user) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. Frontend tasks (T6–T7) follow `frontend-design:frontend-design` and the M1 Design Language (`docs/superpowers/plans/2026-10-30-m1-core-inbox.md`).

**Goal:** Every ticket gets first-response and resolution deadlines from a workspace SLA policy and business-hours calendar; the clock pauses while waiting on the customer; a restart-safe sweeper records "at risk" and "breached" events; people can see, filter by and understand the numbers.

**Architecture:** A pure calculation core (`sla/engine.py`, no I/O) is wrapped by a small service that turns ticket changes into an append-only `sla_events` stream and a rebuildable `ticket_sla` cache. PostgreSQL is the source of truth for deadlines and escalation state. A Celery-beat sweeper (as `rf_system`) selects due rows with `FOR UPDATE SKIP LOCKED`, writes idempotent threshold events and re-schedules; it also back-fills missing rows and recomputes tickets whose policy version is stale, so nothing depends on a queued message surviving a restart.

**Tech Stack:** M1 stack; Python `zoneinfo` for timezones. No new infrastructure or dependencies.

**Spec:** `docs/superpowers/specs/2026-10-30-resolveflow-design.md` §7.3 (SLA engine) and §9 (reliability); PRD FR-11..FR-15, FR-22 (detection part).

## Global Constraints

- Targets are **first-response** and **resolution** per priority `low|normal|high|urgent`; next-response SLA is out of scope (decided).
- Business hours: per-workspace weekly schedule + IANA timezone; holidays are a simple list of closed dates (decided). Each policy has a `business_hours_only` toggle.
- The clock **pauses while status is `pending`** and resumes when the customer replies or status changes (decided).
- One default SLA policy per workspace in v1 (my call, design §14); policy and calendar are edited by Owner/Admin (`settings:update`).
- Warning threshold = **75%** of the target consumed; breach = **100%** (PRD FR-22).
- **Escalation processing is idempotent, concurrency-safe and recoverable after restarts; PostgreSQL is the source of truth for deadlines and escalation state** (user clarification): threshold events carry a unique dedupe key; the sweeper uses `FOR UPDATE SKIP LOCKED`; a cold start catches up from database state alone.
- Pure engine: no I/O, no `now()`; every function takes the instants it needs. DST-correct.
- M2 **detects and records** at-risk/breached state (events, audit rows, badges, views). Delivering alerts to people (in-app/email) is M4; automated escalation actions are M3 rules. No UI for those appears in M2.
- Deferred features never appear in the UI; no mock data; every control calls the real API.
- Branch `m2-sla`; Conventional Commits; push per task; PR + merge + tag `m2-complete` after full verification.

## Review Focus

- A ticket moved to `pending` and back many times, and one resolved then reopened: the due time must equal the hand-computed value (pause time excluded, reopened clock restarts for resolution).
- Business hours across a weekend, a holiday, a DST change, and a ticket created outside working hours (clock effectively starts at the next opening).
- Two sweepers running at once, and a sweeper killed mid-run, must produce exactly one warning and one breach event per ticket/metric; a cold start after downtime must catch up everything overdue.
- Editing the policy or calendar mid-flight must reschedule open tickets (via the version check) without losing already-recorded breaches.
- Tickets of another workspace are never touched by a sweep scoped to one workspace's data; viewers can read SLA info, only Owner/Admin can change settings.

### Task 1: Pure SLA engine

**Files:** Create `sla/engine.py`, `tests/test_sla_engine.py`.

**Interfaces — Produces:**
- `@dataclass(frozen=True) Calendar(tz: ZoneInfo, weekly: dict[int, list[tuple[time, time]]], holidays: frozenset[date])` (weekday 0=Monday; empty list = closed). `Calendar.always_open()` is not needed: `None` means 24x7.
- `Pause = tuple[datetime, datetime | None]` (aware datetimes, end `None` = still paused).
- `compute_due(start: datetime, target_minutes: int, calendar: Calendar | None, pauses: Sequence[Pause]) -> datetime | None` — the instant when `target_minutes` of *running* time (business time if a calendar is given) have elapsed since `start`, skipping pauses; returns `None` while the final pause is still open (clock stopped).
- `elapsed_minutes(start: datetime, now: datetime, calendar: Calendar | None, pauses: Sequence[Pause]) -> float` — running minutes consumed up to `now`.
- `threshold_instant(start, target_minutes, fraction: float, calendar, pauses) -> datetime | None` — `compute_due` for `ceil(target*fraction)`.

### Task 3: Clock state from events

**Files:** Create `sla/service.py`, `tests/test_sla_clock.py`; Modify `services/tickets.py`, `services/messages.py`, `services/ingest.py` (explicit calls inside the same transaction).

**Interfaces — Produces:**
- `service.record_event(ctx: ServiceCtx, ticket_id, kind: str, detail: dict | None = None, at: datetime | None = None, dedupe_key: str | None = None) -> bool` (inserts into `sla_events`; `False` when the dedupe key already existed).
- `service.recompute(ctx: ServiceCtx, ticket_id, now: datetime) -> None` — loads the ticket, policy, calendar and its events; derives: start (earliest `started`, or `reopened` for the resolution clock), pauses from `paused/resumed` pairs, `fr_met_at` (first `first_response`), `res_met_at` (latest `resolved` not followed by `reopened`), targets for the **current** priority, due instants via the engine, 75%/100% instants, and writes `ticket_sla` including `next_check_at` (earliest upcoming unrecorded threshold of an unmet, unpaused metric, else `NULL`). Policy disabled → no `ticket_sla` row/`NULL` deadlines.
- `service.backfill_events(ctx, ticket_id) -> None` — reconstructs events for a ticket created before SLA tracking (started at `created_at`; `first_response` at the first non-note outbound message; `resolved` at `last_activity_at` when status is resolved/closed; `paused` at the last outbound message when status is pending) then recomputes. Used by the migration/seed.
- Hook rules (inside the existing service transactions): ticket created → `started`; status → `pending` → `paused`; leaving `pending` (including an inbound customer message re-opening it) → `resumed`; first non-note outbound message → `first_response`; status → `resolved|closed` → `resolved`; leaving them → `reopened`; priority change → `priority_changed` with `{from, to}`; every hook ends with `recompute`. Merge: the source's clocks stop (`resolved`), the target recomputes.

### Task 4: Sweeper, escalation events and recovery

**Files:** Create `sla/sweeper.py`, `tests/test_sla_sweeper.py`; Modify `celery_app.py` (beat entry `sla-sweep` every 60 s), `tasks/` (new `tasks/sla.py`).

**Interfaces — Produces:** `sweeper.sweep(engine: Engine, now: datetime | None = None, batch: int = 200) -> SweepResult(thresholds: int, recomputed: int, backfilled: int)` and Celery task `resolveflow.tasks.sla.sweep` (runs as `rf_system`). One sweep, in one transaction per batch: (a) `select … from ticket_sla where next_check_at <= :now order by next_check_at limit :batch for update skip locked`; for each, decide which of `fr|res × warn|breach` are due and unrecorded, insert `threshold` events with `dedupe_key = "{ticket}:{metric}:{level}:{due_at_iso}"` (`ON CONFLICT DO NOTHING`), set `*_warned_at/*_breached_at`, write audit `sla.warning` / `sla.breached` (actor `system`), `recompute`; (b) tickets whose `policy_version` differs from `sla_policies.version` are recomputed; (c) open tickets with no `ticket_sla` row get `backfill_events` + `recompute`. Returns counts. Beat is the only scheduler; nothing is queued per ticket.
